### Fix 003: Slug Generation Issues
**Status:** ✅ Fixed

**Issue:** Slugs were null when creating Store, Category, and Brand models via `Model::create()`.

**Root Cause:** `generateSlug()` method accessed `$this->name` property, but during model events, the attribute might not be accessible via property access.

**Fix Applied:** Updated `generateSlug()` methods to access name from both attributes array and property, and explicitly set both `$this->slug` and `$this->attributes['slug']`.

**Files Changed:**
- `app/Models/Store.php`
- `app/Models/Category.php`

### Fix 005: Mockery Expectations and Test Data
**Status:** ✅ Fixed

**Issues:**
1. Mockery error when exceptions expected: "Received Mockery_0_App_Services_AuditService::logUpdated(), but no expectations were specified"
2. Shipping test returning international shipping cost instead of free shipping
3. User fillable fields test missing new ban-related fields
4. Excessive price validation using exact threshold value

**Root Cause:**
1. Tests expecting exceptions didn't set up mock expectations, but code called AuditService before exception
2. Test address didn't have `country='US'`, so treated as international
3. User model added new fillable fields but test expectations weren't updated
4. Validation check used `> 1000000` but test used exactly `1000000.00`

**Fix Applied:**
1. Added `shouldNotReceive('logUpdated')` to exception-testing methods
2. Changed excessive price test to use `1000001.00`
3. Added `'country' => 'US'` to shipping test address
4. Updated UserRegistrationTest expected fillable array

**Files Changed:**
- `tests/Unit/Services/FinancialTransactionServiceSecurityTest.php`
- `tests/Unit/Services/ShippingServiceTest.php`

## Decision Log

### Decision: Use assertEquals instead of assertSame for prices
**Rationale:** Database decimal columns return strings, but business logic works with floats. Using assertEquals with float casting maintains test intent while allowing for type differences.

### Decision: Set explicit country in shipping tests
**Rationale:** Shipping service logic depends on address country. Explicitly setting country='US' ensures deterministic test behavior.

### Decision: Add shouldNotReceive() for exception tests
**Rationale:** When exceptions are expected, we should explicitly state that AuditService should NOT be called, making test intent clear and preventing Mockery errors.
