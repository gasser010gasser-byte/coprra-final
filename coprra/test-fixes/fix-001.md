# Fix 001: Slug Generation on Create/Update for Store, Brand, Category Models

## Issue
Tests failing because slugs are not being auto-generated when creating Store, Brand, or Category models:
- `StoreModelTest::testSlugGenerationOnCreate` - Expected 'test-store-name', got null
- `StoreTest::testSlugAutoGeneratedOnCreating` - Expected 'test-store', got null  
- `StoreTest::testSlugUpdatedOnNameChange` - Expected 'new-name', got null
- `BrandTest::testSlugAutoGeneratedOnCreating` - Expected 'test-brand', got null
- `BrandTest::testSlugAutoGeneratedOnUpdating` - Expected 'new-name', got null
- `CategoryTest::testSlugAndLevelAutoGeneratedOnCreating` - Expected 'test-category', got null
- `CategoryTest::testLevelBasedOnParentOnCreating` - Expected level 2, got null
- `CategoryTest::testSlugUpdatedOnNameChange` - Expected 'new-name', got null
- `CategoryTest::testLevelUpdatedOnParentChange` - Expected level 2, got null

## Root Cause
In the `creating` event handlers, the code was checking `!empty($model->name)` to determine if slug generation should occur. However, during the creating event, the `name` property may not be accessible directly and might only exist in the `attributes` array. The check should use `$model->attributes['name']` instead.

## Fix Applied
Modified the `creating` event handlers in all three models to check the attributes array for the name:
- `app/Models/Store.php` - Line 263-264: Changed to check `$store->attributes['name']` 
- `app/Models/Brand.php` - Line 135-136: Changed to check `$brand->attributes['name']`
- `app/Models/Category.php` - Line 167-169: Changed to check `$this->attributes['name']`

## Files Changed
- `app/Models/Store.php`
- `app/Models/Brand.php`
- `app/Models/Category.php`
