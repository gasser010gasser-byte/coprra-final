# Fix #001: PriceHistory effective_date NOT NULL Constraint Error

## Issue Excerpt
```
1) Tests\Unit\DataAccuracy\PriceHistoryAccuracyTest::testHistoricalPricesAccuracy
Illuminate\Database\QueryException: SQLSTATE[23000]: Integrity constraint violation: 19 NOT NULL constraint failed: price_histories.effective_date
```

## Root Cause Analysis
The migration `2025_10_02_000000_create_price_histories_table.php` was creating the `price_histories` table with `effective_date` as a NOT NULL column, while the model and application code use `recorded_at`. When tests tried to create price history records using `recorded_at`, the database constraint failed because `effective_date` was required but not provided.

Additionally, there were conflicting migrations creating the same table with different structures, causing schema inconsistencies.

## Fix Applied

### Files Changed:
1. `database/migrations/2025_10_02_000000_create_price_histories_table.php` - Updated to create table with correct structure matching the model
2. `database/migrations/2025_11_29_000004_fix_price_histories_schema.php` - Created new migration to handle existing tables and ensure proper schema
3. `app/Models/PriceHistory.php` - Added boot method to handle transition period where `effective_date` column might still exist

### Code Changes:
- Modified the original migration to create table with `recorded_at` instead of `effective_date`
- Added `old_price` and `currency` columns to match model expectations
- Created fix migration to add `recorded_at` to existing tables and migrate data from `effective_date`
- Added model boot method to copy `recorded_at` to `effective_date` during transition period if the column exists
