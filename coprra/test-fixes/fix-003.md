# Fix #003: PriceHistory Factory and Product Model Event Improvements

## Issues Addressed
1. PriceHistoryFactory using old `effective_date` field
2. Product model events not handling errors gracefully

## Root Cause Analysis
1. The `PriceHistoryFactory` was still using the old `effective_date` field instead of `recorded_at`, which could cause issues when using factories in tests.
2. Product model's `created` and `updated` events don't have error handling, which could cause silent failures if price history creation fails.

## Fix Applied

### Files Changed:
1. `database/factories/PriceHistoryFactory.php` - Updated to use `recorded_at` instead of `effective_date`
2. `app/Models/Product.php` - Added error handling and validation to price history creation events

### Code Changes:

**PriceHistoryFactory:**
- Changed `effective_date` to `recorded_at`
- Added `old_price` and `currency` fields to match model structure

**Product Model:**
- Added try-catch blocks around price history creation
- Added validation to ensure price exists before creating history
- Added error logging for debugging
