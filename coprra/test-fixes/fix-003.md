# Fix 003: Product Update API Authorization Route Parameter Mismatch

## Issue
API Integration tests failing with 500 errors when updating products:
- `APIIntegrationTest::testAuthenticatedProductUpdateWithValidDataAndAuditTrail` - Expected 200, got 500
- `APIIntegrationTest::testProductUpdateGeneratesUniqueSlugWithConflictResolution` - Expected 200, got 500
- `APIIntegrationTest::testNonAdminUserCannotUpdateProductWithDetailedPermissionCheck` - Expected 403, got 500
- `APIIntegrationTest::testProductNotFoundReturnsComprehensive404` - Expected 404, got 500
- `APIIntegrationTest::testPriceSearchProductWithNoOffersReturnsComprehensiveOfferState` - Expected 404, got 500
- `APIIntegrationTest::testPublicAPIEndpointsStructure` - Expected 200, got 500
- `PageLoadTimeTest::testProductDetailPagePerformance` - Expected 200, got 500
- `PageLoadTimeTest::testUserDashboardPagePerformance` - Expected 200, got 500

## Root Cause
The `ProductUpdateRequest::authorize()` method was trying to access `$this->route('product')`, but the actual route parameter name is `id` (as defined in routes/api.php: `Route::put('/products/{id}', ...)`). This caused the authorization to fail or throw exceptions, resulting in 500 errors.

Additionally, the method didn't properly handle cases where the user might be null or the product might not exist yet.

## Fix Applied
1. Modified `authorize()` to use `$this->route('id')` instead of `$this->route('product')`
2. Added proper null checks for user and product
3. Updated `getProductIdForRules()` to use the correct route parameter name
4. Allow authorization to pass when product doesn't exist (let controller handle 404)
