# Fix 004: Price Search API Response Format Issues

## Issue
Price search API tests failing due to missing fields and type mismatches:
- `APIIntegrationTest::testPriceSearchBestOfferWithMultipleOffersReturnsLowestPrice` - Expected 'budget-tech' slug, got null
- `APIIntegrationTest::testPriceSearchByProductIdWithComprehensiveOfferData` - Expected 25.0 (float), got 25 (int)

## Root Cause
1. Store relationship in price offers wasn't loading `slug` and `contact_email` fields - only `id` and `name` were loaded
2. Shipping cost and price statistics were not being cast to float, causing type mismatch issues with strict assertions

## Fix Applied
1. Updated all store relationship loading in PriceSearchController to include `slug` and `contact_email` fields
2. Added explicit float casting for shipping_cost, total_cost, and price_statistics values to ensure consistent data types
