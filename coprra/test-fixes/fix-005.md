# Fix 005: Mockery Expectations and Test Data Issues

## Issue
1. `testUpdateProductPriceWithExcessivePrice` - Mockery error: "Received Mockery_0_App_Services_AuditService::logUpdated(), but no expectations were specified"
2. `testUpdatePriceOfferWithInvalidUpdateData` - Same Mockery error
3. `testItReturnsZeroForFreeShippingThreshold` - Returning 25.99 instead of 0.0
4. `testUserHasCorrectFillableFields` - Missing new ban-related fields in expected array

## Root Cause
1. Tests expecting exceptions didn't set up mock expectations, but code still called AuditService before exception was thrown
2. Shipping test address didn't have country='US', so it was treated as international
3. User model added new fillable fields but test expectations weren't updated
4. Validation check used `> 1000000` but test used exactly `1000000.00`

## Fix Applied
1. Added `shouldNotReceive('logUpdated')` to exception-testing methods
2. Changed excessive price test to use `1000001.00` instead of `1000000.00`
3. Added `'country' => 'US'` to shipping test address
4. Updated UserRegistrationTest expected fillable array to include `banned_by`, `unbanned_at`, `unbanned_by`

## Files Changed
- `tests/Unit/Services/FinancialTransactionServiceSecurityTest.php`
- `tests/Unit/Services/ShippingServiceTest.php`
- `tests/Unit/UserRegistrationTest.php`
