# Fix #005: FinancialTransactionService Validation Improvements

## Issues Addressed
1. testCreatePriceOfferWithExcessivePrice - Price validation not catching boundary value
2. testUpdatePriceOfferWithInvalidUpdateData - Validation not checking `price` field directly

## Root Cause Analysis
1. The test used 1000000.00 which passes validation because the check is `> 1000000` (strictly greater), so exactly 1000000 passes. The test should use 1000001.00.
2. The `validateOfferUpdateData` method only validated `new_price` field, but the test and service code also use `price` field directly. Validation should check both.

## Fix Applied

### Files Changed:
1. `tests/Unit/Services/FinancialTransactionServiceSecurityTest.php` - Updated test to use price that exceeds limit
2. `app/Services/FinancialTransactionService.php` - Enhanced validation to check both `price` and `new_price` fields

### Code Changes:
- Updated test to use 1000001.00 instead of 1000000.00 to properly exceed the validation threshold
- Added validation for `price` field in addition to `new_price` in `validateOfferUpdateData()`
- Added maximum price limit check to update validation for consistency
