# Fix 008: AdminMiddleware Permission Test Failure

## Issue Excerpt
```
63) Tests\Unit\Middleware\AdminMiddlewareTest::testAdminPermissionLevelsAndRoleValidation
User with role admin should not have access to /admin/system-settings
Failed asserting that 404 is identical to 403.
```

## Root Cause Analysis
The test expects that a user with role 'admin' should get a 403 (Forbidden) response when accessing `/admin/system-settings`, but the route didn't exist, causing Laravel to return 404 (Not Found) before the middleware could deny access.

## Fix Applied
1. Created the `/admin/system-settings` route in `routes/web.php`
2. Added `systemSettings()` method to `AdminController` that checks for `system.settings` permission
3. The method returns 403 for users without the permission (regular admin users), and only allows super_admin users who have the `system.settings` permission

## Files Changed
- `routes/web.php` (added system-settings route)
- `app/Http/Controllers/AdminController.php` (added systemSettings method)
