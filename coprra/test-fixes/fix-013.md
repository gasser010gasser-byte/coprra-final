# Fix 013: Memory Exhaustion in AnalyticsService::sanitizeMetadata()

## Issue
`AnalyticsServiceEdgeCaseTest::testTrackWithMemoryExhaustion` caused PHP Fatal error: Allowed memory size of 2147483648 bytes exhausted in `/var/www/app/Services/AnalyticsService.php` on line 295.

WorkerCrashedException for `tests/Unit/Services/AnalyticsServiceEdgeCaseTest.php` with Exit Code: 255.

## Root Cause
The `sanitizeMetadata()` method recursively processes arrays without any depth limit or size checks. When processing extremely large nested arrays (e.g., 1 million elements with 1000-character strings), the recursive processing exhausts available memory, causing the worker process to crash.

Additionally, the `AnalyticsEvent` model had a corrupted PHPDoc comment on line 19 that incorrectly referenced `\App\Models\Brand` instead of `\App\Models\AnalyticsEvent`, causing static analysis errors.

## Fixes Applied
1. Added depth limit (max 10 levels) to `sanitizeMetadata()` to prevent infinite recursion
2. Added size check (max 1MB serialized) to reject extremely large metadata before processing
3. Added proper handling when metadata exceeds limits - method returns null and logs warning
4. Updated `track()` method to detect when metadata was rejected and return null with warning
5. Fixed corrupted PHPDoc in `AnalyticsEvent.php` line 19
6. Updated test to use reasonable metadata size that triggers the limit check instead of trying to exhaust memory

## Files Changed
- `app/Services/AnalyticsService.php` - Added depth and size limits to `sanitizeMetadata()`, improved `track()` handling
- `app/Models/AnalyticsEvent.php` - Fixed corrupted PHPDoc comment
- `tests/Unit/Services/AnalyticsServiceEdgeCaseTest.php` - Updated `testTrackWithMemoryExhaustion()` to test size limit instead of memory exhaustion
